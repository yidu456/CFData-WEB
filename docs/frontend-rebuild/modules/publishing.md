### G07 发布目标与账号管理

管理入口统一，平台配置和执行逻辑分开。现有 GitHub/edgetunnel 文本上传可以复用结果输出能力；后续 DNS 推送使用结构化 IP 结果生成解析记录，不直接上传 TXT/CSV。

| 编号 | 功能 | 状态与边界 |
|---|---|---|
| P01 | 上传结果到 GitHub | Web 已有；owner/repo、分支、目标路径、提交信息、Token |
| P02 | 快速上传指定本地文件到 GitHub | Web 已有；此时使用文件内容，不用上方结果内容；旧入口仍藏在结果操作弹窗中 |
| P03 | GitHub 新建/选择/删除账户配置 | Web 已有；上传时保存账户元数据，显示 Token 摘要；账号存在不等于凭据可用 |
| P04 | 可选记住 Token 与旧存储迁移 | Web 已有；WebCrypto AES-GCM 存储；不支持加密时本次上传可继续但不持久保存 |
| P05 | GitHub 上传进度、重试与结果 | Web/后端已有；最多 3 次尝试，返回 Raw URL，成功后可复制；失败附代理提示 |
| P06 | 上传结果到 edgetunnel | Web 已有；域名、密码，登录获取 Cookie 后写入远程 ADD.txt |
| P07 | edgetunnel 覆盖/追加上传与确认 | Web 已有；追加会先读远端内容；读失败时后端当前会降级为覆盖，见迁移风险 |
| P08 | edgetunnel 新建/选择/删除账户 | Web 已有；可选加密记住密码，解密失败需要重新输入 |
| P09 | 两种模式的完成后自动上传 | Web 已有；仅 GitHub，使用默认字段和当前全量结果，不套用手动输出范围/筛选 |
| P10 | 自动上传去重、空结果/缺凭据反馈 | Web 已有；同任务重复完成事件不应重复提交；页面断开后不保证执行浏览器自动上传 |

安全边界：凭据保存在浏览器，上传请求经后端发送。不能把“加密存储”宣传成能防同源脚本/XSS，也不能把 Token/密码回填到日志或普通配置导出中。

主要依据：`uploadSelectedResultsToGitHub`、`autoUploadResults`、`uploadToEdgetunnel`、`saveCurrentGitHubAccount`、`saveCurrentEdgetunnelAccount`。

## 新增需求：统一发布目标管理

用户要求：现有上传配置和未来 DNS 管理商配置集中管理，推送时只选择已经保存的目标。这是后续重构需求，不属于上表已经实现的 P01-P10。

### 对用户的操作方式

```text
发布目标管理 -> 新建目标 -> 选择已接入的平台
  -> 填写该平台的认证、目的地和推送规则 -> 保存
结果工作区 -> 选择结果与发布目标 -> 预览影响范围 -> 推送
自动流程 -> 选择同一份已保存目标，不另外填写平台配置
```

- 用有意义的目标名称选择，如“优选列表仓库”“订阅服务”“家庭域名解析”，不要求用户记住 Token、Zone ID 或仓库路径。
- 同一个平台允许保存多个目的地；目标名称可修改，但任务引用稳定 ID，不引用数组下标或显示名称。
- 列表展示平台、目的地摘要与配置是否完整；不在列表显示密钥。
- 配置编辑与推送分离：推送对话框不重复塞入所有平台的账号表单。
- 尚未接入的平台不能显示成可正常推送的目标；不预建没有能力的空 DNS 插件。
- 首版不默认增加多目标批量推送；如确认需要多选，须逐目标反馈成功/失败，不能把部分成功显示成全部成功。

### 一份目标配置包含什么

| 配置部分 | 共通信息 | 平台差异 |
|---|---|---|
| 身份 | 稳定 ID、名称、平台类型 | 不同平台无需相同认证字段 |
| 认证 | 已配置状态和安全存储的凭据/引用 | GitHub Token、edgetunnel 密码、未来 DNS API 凭据 |
| 目的地 | 对用户可读的摘要 | 仓库/分支/路径、服务域名、DNS Zone/记录名 |
| 推送规则 | 本次动作及影响范围 | 文件更新、追加/覆盖、指定 DNS 记录更新 |
| 默认结果转换 | 该目标支持的输出选择 | 文件目标使用 TXT/CSV；DNS 目标使用合法 IP 生成 A/AAAA |

首版只做完成这些需求的目标配置，不提前建设多租户、组织、角色和通用工作流引擎。共用管理不意味着把所有平台字段做成一个无校验的大 JSON 表单。

### DNS 推送单独处理的边界

- 从结构化优选目标 IP 取值，明确 IPv4 -> A、IPv6 -> AAAA；不把端口、TXT 的 `#` 注释或出站 IP 字段误写为解析值。
- Zone/域名、记录名、记录类型、TTL 等配置按接入的平台支持情况校验；不为没有此能力的平台显示无效选项。
- “覆盖”只能针对明确选择的记录或受本工具管理的集合，不能解释为删除整个域名下的其他解析记录。
- DNS 与文件上传使用各自转换器；改变 TXT 分隔符不能影响 DNS 记录值。
- DNS API 请求和凭据校验由后端处理，不让浏览器直接携带密钥调用管理商 API。
- 具体 DNS 管理商、更新单条还是多条记录、删除旧记录策略尚未确认，不在本轮写死。

### 对开发和维护的边界

```text
结果模块 -> 结构化候选/输出内容
目标管理 -> 已保存目标及平台配置
推送编排 -> 按目标类型交给具体平台实现
平台实现 -> 认证、参数校验、结果转换、请求、错误解释
```

前端统一列表和选择体验；GitHub、edgetunnel、未来每个已接入 DNS 管理商分别维护平台配置与后端推送实现。新增平台不应修改官方扫描、非标扫描、表格渲染或复制格式。

现有两个平台继续保留各自可用动作。不能为了统一而把 GitHub 的 Raw URL、edgetunnel 的追加/覆盖或未来 DNS 的记录配置藏掉。

### 存储与兼容

现有账号在浏览器 localStorage 中，自动上传目前也由浏览器触发。统一管理不等于已经提供跨设备共享或无页面后台推送。

- 新模型需要读取/迁移旧账号数据；迁移成功前不删旧数据，不能因改名/重排导致任务推送到错误目的地。
- 普通任务参数保存与发布凭据分开；凭据不得进入日志、预览、普通配置下载或失败提示。
- 若要求跨设备管理、CLI 共用目标或页面关闭后的可靠自动推送，则需要后端持久化目标与凭据并承担执行；这是待确认的架构范围，不仅是前端文件拆分。

### 新增验收项（未来实现时执行）

- [ ] 新建、编辑、删除现有平台目标后，手动推送只需选目标和结果。
- [ ] 手动与自动流程引用同一目标；改名或列表重排不改变目的地。
- [ ] 缺失认证/目的地、被删除的目标、未接入的平台均有明确反馈。
- [ ] 旧 GitHub/edgetunnel 配置不丢失，现有平台特有功能继续可用。
- [ ] DNS 更新前可确认域名/记录/类型/数量，失败不误删无关解析。
