### G04 全局任务与后台监控

独立于任务参数和结果输出。用户切换工作区时应仍然看得到任务状态，不要绑定某张旧表格的可见性。

| 编号 | 功能 | 状态与边界 |
|---|---|---|
| T01 | 开始任务与全局运行互斥 | Web/后端已有；跨浏览器连接也互斥；已有任务时给出明确原因 |
| T02 | 阶段进度、数量统计和运行名称 | Web 已有；准备、扫描、详细测试、复验、测速、整理、停止、完成等 |
| T03 | 停止任务与二次确认 | Web 已有；异步发取消信号，展示“正在停止/整理”，不是立即清空结果 |
| T04 | 停止后的已有结果整理 | Web/后端已有；官方扫描/详细测试、非标扫描/测速分别回传可用结果 |
| T05 | 转入后台运行与确认说明 | Web 已有；关闭/刷新页面不取消后台任务；不转后台时断开连接会取消运行任务 |
| T06 | 重新连接时发现后台任务 | Web 已有；显示来源、阶段、进度、扫描/测速等统计 |
| T07 | 后台状态轮询与跟随实时数据 | Web 已有；跟随后接收未来数据；不回放断线期间全部中间行 |
| T08 | 已完成后台任务的最终结果获取 | 后端/前端已有；官方汇总和详细结果、非标最终 CSV 有回传路径；不是完整扫描事件历史 |
| T09 | 后台任务停止、完成、消失 | Web 已有；后续开始新任务会清理已完成后台任务快照 |
| T10 | 连接状态与自动重连 | Web 已有；WS/WSS 跟随当前协议，断线后 3 秒重连并复位前台运行状态 |
| T11 | 完成、部分完成、失败、停止、限流分别反馈 | Web 已有；尤其不能收到通用 `task_complete` 就抹掉更具体的终态 |
| T12 | 日志和错误反馈 | Web 已有；带时间、自动滚动、服务端错误、解析/请求/网络错误、调试记录 |

边界：后台状态在进程内存中，不提供数据库历史、任务队列或重启恢复；跟随操作会将该会话的 WebSocket 换到当前连接，不是多订阅者广播系统。

主要依据：`startTaskNamed`、`beginTask`、`shouldCancelOnDisconnect`、`backgroundSummary`、WebSocket 的后台 handlers、`handleMessage`。
