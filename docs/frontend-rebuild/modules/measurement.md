### G03 共享测量与测速能力

可共享配置控件、状态表达和操作语义，但官方与非标的执行算法、结果来源和并发能力不能强行统一。

| 编号 | 功能 | 状态与边界 |
|---|---|---|
| S01 | 测速地址预设与手动输入 | Web 已有；自动、Cloudflare、CM 提供、移动专属、自定义，支持恢复自动选择 |
| S02 | 后端自动测速源选择 | 后端已有；结合运营商识别和可用源选择/回退；不是按浏览器所在地区选源 |
| S03 | 内置测速源可用性预检与提示 | Web 已有；下拉选项标注不可用；有状态查询接口，没有“强制重新预检所有源”的现成接口 |
| S04 | 测速合格速度和合格结果数量上限 | Web 已有；默认 0.1MB/s、5 个；0 个关闭测速；上限指达标数量，不是最多尝试数量 |
| S05 | 一键测速与重新测速 | Web 已有；非继续模式会重置前端速度数据；后端按各自结果集处理 |
| S06 | 继续测速 | Web 已有；跳过已测速行，保留已有速度/达标结果；不等于“重试所有失败行” |
| S07 | 测速四种基础状态 | Web 已有；未测速、达标、未达标、失败；失败原因不能被显示为数值 0 |
| S08 | 测速进度与达标统计 | Web 已有；进度中的合格数/目标上限和尝试数/总候选数不是同一个指标 |
| S09 | 官方测速限流停止 | Web 已有；连续 3 次速率限制后停止，说明稍后重试/换网络；已有结果仍需保留 |
| S10 | 两种测速执行方式 | 后端已有；官方批量顺序测速并间隔等待；非标允许配置并发，不能假装官方也支持同一测速并发设置 |

主要依据：`resolveStartupSpeedTestURL`、`speedURLStatusPayload`、`runOfficialSpeedBatch`、`runNSBSpeedBatch`、`getSpeedStatus`。
