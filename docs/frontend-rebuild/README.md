## 1. 范围与结论

- 主体：`CFData-WEB/combined_refactor/` 的 Go 后端、嵌入式 `index.html`、`login.html`。
- 兼容对象：Android WebView 包装层、CLI 配置文件及当前 WebSocket 协议。
- 单独登记：CLI/系统级能力和独立仓库 `Cloudflare-BestIP`，不混入已有 Web 功能。
- 不以顶层参考 Go 源码或历史前端分支为功能依据。
- 已整理 **11 个功能组、112 项功能/兼容约束、20 个 WebSocket 请求入口、41 种旧前端处理的事件类型**，附 61 个关键函数源码位置和 28 个跨模块验收场景。源码中的字面量 `sendWSMessage` 事件均有对应前端分支；这不等于运行时所有流程已验证。

**核心分组：两种任务入口 + 共享执行/测速能力 + 三类结果 + 共享输出/发布能力 + 独立设置与维护。**

“完全重做 UI”不等于重写算法、协议或凭据存储。第一轮可以换掉全部视图实现，保留后端行为；如需改变流程编排、协议、Android 桥接或数据持久化，应另行确认。

## 6. 建议信息架构：功能组不等于一级菜单

推荐 **“双模式优选工作台 + 全局任务区域 + 结果工作区 + 设置/发布管理”**，不机械地为 11 个功能组创建 11 个页面。

```text
登录（启用认证时）
应用壳：连接状态、当前任务摘要、必要环境提示
优选工作台
  官方任务：来源/扫描 -> 数据中心 -> 详细测试/测速
  非标任务：来源/扫描 -> 复验/测速
任务监控：进度、后台、跟随、停止、日志
结果工作区：按三类结果查看 -> 筛选排序 -> 输出配置 -> 复制/下载/发布
设置
  任务参数的保存与加载、主题
  统一发布目标管理：现有 GitHub/edgetunnel；按需接入 DNS 管理商
  管理面网络与诊断
  地址库/数据缓存维护
  版本信息；认证相关入口按后端可用能力提供
```

“任务监控”和“结果工作区”是逻辑区，可以是页面、面板或详情区域，尚未决定具体布局。

备选方案：

1. **推荐：上述工作台。** 少切页，官方与非标共用结果/输出体验，同时保留不同工作流。
2. **两个完全独立的工具页面。** 最容易对照旧功能，但任务、输出和设置容易重复，切换时易丢全局状态。
3. **从输入到发布的纯向导。** 新手清晰，但反复换 DC、重测速、复验和后台跟随不适合强线性流程。

这些建议未引入历史任务、任务队列、多人权限或新调度系统，也不预先选择前端框架。

## 后续新增需求
