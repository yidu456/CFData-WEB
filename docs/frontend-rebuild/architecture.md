# 模块边界与开发原则

[返回总览](README.md) | [统一发布目标](modules/publishing.md)

本文是架构建议，不代表已实现或已批准的具体 UI。

## 5. 哪些放一起，哪些必须分开

| 关系 | 建议 | 原因 |
|---|---|---|
| 官方扫描 + 数据中心汇总 + 详细测试 | 放在同一个官方任务工作流，分阶段 | 后一阶段依赖前一阶段结果 |
| 非标输入 + 扫描 + 复验 + 自动测速 | 放在同一个非标任务工作流 | 共用候选与参数，保持来源可追溯 |
| 官方与非标入口 | 同一个“优选”区域内两个任务类型 | 服务同一目标，但来源/流程不同，不能硬合并参数 |
| 测速网址 + 合格速度 + 合格数量 | 合为测速参数组 | 共同定义测速行为和达标语义 |
| 扫描并发与测速并发 | 分开 | 不同资源消耗；官方没有同样的测速并发功能 |
| 扫描合格数量与测速合格数量 | 分开 | 不同阶段、不同达标定义，不能共用“结果上限” |
| 数据中心手动选择与非标 DC 过滤 | 分开表达 | 一个驱动下一阶段，一个约束当前扫描 |
| 运行控制 + 后台状态 + 进度 + 日志 | 统一任务区域，处于全局层 | 不应随模式切换消失 |
| 结果筛选 + 结果排序 | 放在结果工作区的同一操作组 | 都改变结果浏览方式 |
| 浏览筛选、输出筛选、任务执行门限 | 数据模型和文案分开 | 当前三者作用范围不同，不能误删或误导 |
| 批量复制 + 文件导出 | 共用输出配置能力，保留两种动作 | 字段/顺序/范围/预览相似，目的不同 |
| 输出配置 + 发布结果 | 文件上传复用生成内容，DNS 推送读取结构化 IP | 内容格式不是认证配置，DNS 不是文本上传 |
| GitHub + edgetunnel + 未来 DNS 管理商 | 统一保存/选择目标，各平台分别配置和执行 | 统一管理体验，不强行统一认证与写入语义 |
| 账号管理 + 自动上传目标选择 | 管理集中，任务只选择目标 | 不要在每个模式重复输入 Token/密码 |
| 浏览器保存参数 + 服务器 CLI 配置 | 分来源展示 | 前者可保存，后者当前只有读取接口 |
| 主题偏好 + 任务参数 | 同属设置但独立存储 | 不应加载任务参数时覆盖主题 |
| 管理面代理 + 地区/VPN警告 | 分成两组 | 一项控制管理请求，另一项评估测量环境 |
| 地址库精简 + 扫描结果筛选 | 完全分开 | 前者会改服务端文件，后者只改显示 |
| 缓存清理 + 删除浏览器配置 | 完全分开且分别确认 | 删除对象、恢复方式和影响范围不同 |
| CLI 定时任务 + Web 后台运行 | 完全分开 | systemd 定时新启动与当前进程任务脱离页面不是一回事 |
| Cloudflare-BestIP 看板 + CFData 工作台 | 独立产品边界 | 不共享后端/协议，也没有现成 KV 发布集成 |

## 对用户友好

- 优选任务按“输入与扫描、验证与测速、结果、发布”组织；高级参数渐进展示，但不能删除功能。
- 始终可见当前任务及停止入口；不要求用户留在某个模式的表格页才知道后台状态。
- 发布配置只在目标管理中填写，执行时选择目标；按平台展示必要字段，不把所有认证项塞在结果弹窗。
- 数据缺失、未测速、失败、限流、部分完成有可辨识状态；确认框说明具体影响对象和数据范围。
- 手机、键盘、屏幕阅读器的操作路径一起验收；不把仅 hover、横向溢出的按钮或颜色当唯一信息载体。

## 对开发者友好：源码按业务边界拆分

下面是建议结构，不是已经创建的应用目录，也不预先决定框架或构建工具。

```text
combined_refactor/
  web/
    index.html                 应用入口，不承载全部业务脚本/样式
    login.html                 登录入口
    styles/                    设计变量、基础规则、布局；领域样式随模块组织
    app.js                     初始化和模块装配，不实现扫描/发布业务
    api/                       HTTP/WebSocket 连接、消息解码与协议适配
    features/
      official/                官方参数、DC 阶段与视图
      nonstandard/             输入、扫描、复验阶段与视图
      measurement/             共用测速参数/状态表达
      tasks/                   全局生命周期、后台状态与监控
      results/                 结果模型、筛选排序、输出与视图
      publishing/              目标管理、选择器、已接入平台配置视图
      settings/                参数偏好、网络与维护视图
    platform/                  Android 导出/主题等环境适配
```

- 以领域目录组织，每个模块在需要时拆视图、状态和纯业务函数；不一次性创建没有逻辑的空壳文件。
- API 层不操作 DOM；视图不直接拼接所有平台请求；模块之间通过明确数据和操作边界连接。
- 全局任务状态只由任务模块维护；结果模块维护全量结果与显示/输出规则，不用 DOM 当数据存储。
- 通用层只收确实被多个模块使用的能力，不把所有未知归属代码塞进 utils.js。
- 后端推送实现也按已接入平台分文件；校验和错误处理留在具体平台边界，不写一个跨平台巨大 switch 包办全部逻辑。
- 不手写一个巨型源码文件；将来构建产物即使打包成单个文件，也不改变源文件的领域边界。

## 对维护友好

- 各模块有明确职责、依赖和对应验收项；新增发布平台只触及发布模块、接口/存储及其测试。
- 协议与数据单位集中维护；不在各张表格重复猜测字符串/纳秒/比例的含义。
- 测试优先覆盖转换、筛选排序、目标校验、任务阶段和消息次序；发布测试 mock 网络，不使用真实密钥。
- 数据迁移显式版本化并兼容旧浏览器账号/参数，不用清空用户配置“解决”重构不兼容。
- 本目录按功能、契约、风险和验收分别维护；修改能力时同步相关模块文档和验收，而不是复制完整清单到多个文件。

## 发布与平台约束不能随拆文件丢失

- 当前 Go 仅嵌入 index.html/login.html/favicon.png；未来拆出的 JS/CSS 必须调整嵌入范围及静态资源路由并按正确 MIME 提供，不能仅把文件放到磁盘就认为发布包能访问。
- 保持本地后端和 Android 包装层可用；资源加载路径不依赖开发服务器或必须联网的 CDN。
- Android 导出和主题集中在平台适配层，保持旧桥接契约或与包装层一起更新，不向其他模块散布临时全局函数。
- 本次未选定框架、未添加依赖、未变更接口；真正实现前还需确认页面结构、目标存储位置和首个 DNS 平台。
