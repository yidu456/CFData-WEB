## 每阶段固定流程

1. 更新本阶段计划与功能覆盖，先写失败测试并确认失败原因。
2. 按领域文件实现真实能力；修复测试，不加入没有请求的抽象或空平台。
3. 跑 Node/Go 相关测试、`go vet ./...`、浏览器交互/布局检查；网络和发布测试使用 mock，不使用真实密钥。
4. 完成代码审查，解决重要问题；`CGO_ENABLED=0 GOOS=linux GOARCH=amd64` 构建到 `release_assets/cfdata-test`。
5. 只暂存本阶段源码、测试和文档，检查 staged diff；忽略构建、缓存、密钥和本地研究账本。
6. 单独本地提交，核对提交内容后直接进入下一阶段；不执行 `git push`。

远端权限不再阻塞下一阶段。未经新的明确授权，不进行 Git 推送；UI 的发布目标功能与 Git 提交是不同概念。
