## 2. 按业务流程整理，而不是按旧界面的按钮整理

### 2.1 官方优选

```text
选择 IPv4/IPv6 和测试参数
  -> 从本地地址库读取，缺失时下载
  -> 按子网抽样并扫描
  -> 扫描结果 + 数据中心汇总
  -> 选择某个数据中心，或自动选择
  -> 多次详细延迟/丢包测试
  -> 单 IP 测速 / 一键测速 / 继续测速
  -> 筛选排序、复制、导出、上传
```

自动流程为：扫描 -> 指定/自动选择数据中心 -> 详细测试 -> 批量测速。前台由浏览器串联后续任务，转入后台后由后端继续执行；不能仅保留“自动测速”开关而遗漏阶段转换。

### 2.2 非标优选

```text
本地 TXT/CSV 或网络 URL（二选一）
  -> 解析端点、去重、域名解析
  -> TCPing/HTTPing 扫描、延迟与数据中心约束
  -> 可选真实链路复验，剔除不可用候选
  -> 可选自动测速
  -> 实时结果 -> 最终 CSV 结果
  -> 后续手动链路复验 / 一键测速 / 继续测速
  -> 筛选排序、复制、导出、上传
```

现状：开启非标自动测速后，即使链路复验选择“关闭”，也会使用公共探针执行复验。手动复验也允许在下拉框关闭时使用公共探针。新界面应明确表达这种联动；若改成真正独立开关，就是业务行为变更。

### 2.3 共用流程

```text
连接和初始化 -> 环境检查/确认 -> 开始任务
  -> 进度、统计、日志、实时结果
  -> 停止并整理已有结果，或转入后台
  -> 完成 / 部分完成 / 失败 / 限流
  -> 查看结果 -> 配置输出 -> 下载或发布
```

同一后端进程全局只允许一个扫描/测试类任务运行，不是“每个页面一个任务”。上传是独立异步处理，不走扫描任务的全局互斥入口。
